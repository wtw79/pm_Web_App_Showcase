88 个自动化测试用例：一场拍卖的数字化护航

August 12, 2026

拍卖现场没有"重启再来"的机会，核心竞价逻辑的质量保障因此成为一等公民。项目用 Vitest 搭建了三层测试体系，共 88 个自动化用例，npm test 全绿。

测试分布

层用例数覆盖
单元测试80报价逻辑 32 · 公式引擎 11 · 格式化 12 · 模板解析 9 · 报表 4 · 状态迁移 14
集成测试8起拍 → 报价 → 领先 → 撤回 / 删除 → 重新开始 → 成交 → 报表的完整闭环

三个真实的回归用例

  • 报表「轮次残留领先」：历史数据 d1 字段残留导致后续轮次仍显示领先。修复为渲染时按规则重算状态，并加入回归用例锁定。
  • 模板无幅度列继承默认：Excel 导入模板没有竞价幅度列时，导入标的幅度继承当前激活标的的竞价幅度，而不是归零导致无法加价。
  • 删除当前标的回未选态：删除正在使用的标的时 activeId 必须回退为 null（保持"未选择"），而不是自动选中第一个——避免"标的复活 + 误选中"的诡异体验。

为什么值得

这些用例不是 KPI 装饰，而是每次 npm run build 与发版前的安全网：88 个用例覆盖了报价校验、状态机、成交规则、模板闭环等全部高风险路径。功能可以迭代，规则不能回退——回归测试就是这句话的保证。
