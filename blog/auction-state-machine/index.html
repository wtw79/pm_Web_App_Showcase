竞价状态机：未开始 → 进行中 → 成交 / 流拍

August 18, 2026

竞价核心逻辑按拍卖行业标准流程严谨实现。一个标的的生命周期是一条清晰的状态机：

未开始 → 进行中（isBeginPaiMai）→ 暂停（isPaused）
                                → 已成交（isClosed + 成交）
                                → 流拍（isClosed + 流拍）

报价记录三态

每条报价记录 { round, d1, d2, d3, d4..d8 }，其中 d1 是状态、d2 是号牌、d3 是金额。records 数组最新在前，records[0] 恒为当前领先：

  • 领先：当前最高价（进行中，多笔同价并列均领先）
  • 出局：被更高价超越
  • 成交：确认成交后锁定唯一一笔

渲染报表 / 控制台时按规则重算每条记录状态，修复了历史数据 d1 残留导致"轮次 3 还领先"的 bug——状态永远由数据推导，不信任持久化字段。

防错设计

  • 报价校验：号牌纯数字、价格有效、增价不低于起拍价、减价不高于起拍价
  • 撤回上一手：records.shift()，次席自动晋升领先
  • 删除任意行可撤销：删除时压入 deletedRows 撤销栈 { record, index }，可精确还原到原位置与领先状态
  • 重新开始带快照：清空前保存 restartSnapshot，可随时恢复
  • 成交前二次校验：确认成交时再次执行 validatePriceRules 复核领先记录，非法数据进不了归档

增价与减价

auctionMode 为 1 是增价（每手至少加一个幅度），-1 是减价（荷兰式，每手往下减）。校验方向、下一手建议价计算（基准 + 幅度 × 方向）、大屏"增价幅度 / 减价幅度"标签都随模式切换，与原版行为一致。
