全局状态使用 **React Context + useReducer**（不引入外部状态库），一套 `store.jsx` 同时服务主控台与投屏窗，靠 `persist` 开关区分读写模式。

## State 结构

```ts
{
  config: {},             // 系统配置（DEFAULT_CONFIG 合并）
  projection: { bid, welcome }, // 投屏状态
  projCtl: {},            // 投屏控制共享态（翻页/缩放/自动）
  targets: [],            // 标的数组
  activeId: null,         // 当前激活标的
  view: "console",        // 当前视图
  reportTargetId: null,   // 报表焦点标的
}
```

## 主控台（persist=true）：防抖双通道

1. **同步初值**：优先 `localStorage`（`auction-web-state-v1`）避免白屏，宿主持久化挂载后异步重载；
2. **config 即时通道**：config 变化 → 50ms 防抖 → `pushConfig`——仅内存广播不落盘，副屏"即改即现"（主题/字号实时生效）；
3. **整份 state 落盘**：300ms 防抖 → `localStorage` + `pushState`（主进程 SQL 落盘 + 广播投屏窗）。

防抖避免每次按键即全量序列化阻塞 UI。

## 投屏窗（persist=false）：只读订阅

```text
挂载 → requestState()（≤8 次重试回拉权威态）+ requestConfig()
     → 订阅 onStateSync → dispatch('RELOAD')
     → 订阅 onConfigSync → dispatch('MERGE_CONFIG')
```

只读不回写，不形成回环。

## 主进程权威态（单一数据源）

`ipc-hub.cjs` 持有 `canonicalState` / `canonicalConfig`：

```text
控制台 push-state
  → db.persist(state)        # SQL 落盘
  → canonicalState = state   # 更新权威态
  → broadcastToDisplays('state-sync')  # 广播所有投屏窗
```

投屏窗崩溃重启后可立即 `request-state` 回拉最新态，状态不丢。

## normalizeState：向后兼容

旧版本持久化的状态缺少新字段（`cnHeaders` / `projection` / `c1..c4` 等），加载时统一补齐；旧分页标题字段（`welcomeTitle`/`bidMainTitle` 8 字段）合并为新版共用 4 字段；旧分页背景合并为单一 `backgroundImage`；空公式回退默认（`DD/C1`、`DD/C2`、`DD/(C1*C2)`）——保证旧数据刷新即用、不崩。
