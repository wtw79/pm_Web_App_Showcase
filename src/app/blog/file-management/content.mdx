成交报表、现场截图、欢迎页媒体，都会自动归档到系统目录。但归档之后的日常管理——核对、导出、清理——过去要人工打开系统文件管理器，逐层翻找。这份方案把文件管理收进系统内。

## 设计原则

- **以标的为中心**：同一标的的欢迎页媒体、竞价页图片、成交归档聚合在一起，不跨目录翻找
- **不改变物理归档结构**：逻辑/类型视图都是对现有目录的不同呈现，存量兼容、零迁移
- **与系统文件管理器一致的操作体验**：双击预览、右键菜单、多选、回收站删除

## 两种视图

| 视图 | 说明 |
|------|------|
| **逻辑视图（默认）** | 按标的聚合：每个标的分组显示「欢迎页 PDF / 欢迎页图片 / 竞价页图片 / 成交报表 / 成交截图」，文件缩略图直览 |
| **类型视图** | 下拉切换：全部媒体（含 PDF）/ 全部成交报表 / 全部成交截图，按时间倒序全局巡检 |

## 核心功能

- **预览**：图片内嵌缩放与同组切换；PDF 复用投屏渲染引擎（支持滚动翻页）；Excel/文本下载打开
- **下载 / 导出**：单个文件保存对话框导出；多选 **zip 打包下载**
- **删除**：移入**系统回收站**（可恢复），媒体列表同步移除该文件；数据库文件只读保护
- **系统资源管理器入口**：在文件管理内直接打开/定位归档目录（工具栏「打开位置」）
- **搜索 / 刷新 / 重命名**：跨标的搜索、F5 刷新、文件重命名
- **类别筛选**：逻辑视图按 **PDF / 图片 / 报表 / 截图** 四类多选过滤（默认全开），媒体（欢迎页图 + 竞价页图）与 PDF 可分别筛选，界面聚焦

## 安全与一致性

- 访问白名单仅限归档根（`AuctionData`），主进程校验路径，拒绝越界
- 删除/覆盖/移动需确认；数据库文件与使用中文件受保护
- 文件操作同步媒体台账，标的目录重命名默认禁止（防止引用失效）

## 与其他上传 / 媒体入口的职责边界

系统里有多个"放文件"的入口：控制台的欢迎页区、标的详情的媒体 tab、系统设置（系统背景），加上文件管理——容易互相打架。设计上按**业务层与文件层分离**化解：

| 入口 | 职责 | 是否改业务字段 |
|------|------|--------------|
| 控制台 · 欢迎页区 | 绑定欢迎页 PDF / 图片（业务操作） | 是 |
| 标的详情 · 媒体 tab | 管理标的媒体（业务操作） | 是 |
| **文件管理 Tab** | **归档文件运维**（浏览/整理/导出/清理/上传落盘） | **否**（上传不隐式改业务） |
| 系统设置 | 系统背景等全局素材（配置域） | 是（全局字段） |

联动规则：

- **上传**：文件管理只把文件放进归档目录（写文件台账）；要"设为欢迎页图片/标的图片"时，去对应业务入口选择（文件管理提供复制路径辅助）
- **删除**：文件管理回收站删除被业务引用的文件时，媒体列表**同步移除**该引用（无状态残留）
- **关联标注**：逻辑视图中被业务引用的文件带标记（"欢迎页"/"标的图片"），删除前提示影响范围
- **边界**：系统背景等全局素材归系统设置，不与归档文件混同

这样每个入口职责单一：业务字段只由业务入口写，文件管理只管文件，删除有明确联动，不会出现"上传了却不知道影响哪里"的混乱。
