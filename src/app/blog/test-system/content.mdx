拍卖现场没有"重启再来"的机会，核心竞价逻辑的质量保障因此成为一等公民。项目用 Vitest 搭建了三层测试体系，共 **88 个自动化用例**，`npm test` 全绿。

## 三个真实的回归用例

- **报表「轮次残留领先」**：历史数据 `d1` 字段残留导致后续轮次仍显示领先。修复为渲染时按规则重算状态，并加入回归用例锁定。
- **模板无幅度列继承默认**：Excel 导入模板没有竞价幅度列时，导入标的幅度继承当前激活标的（对齐 pm 的 `QiPaiZengJiaJinEr`），而不是归零导致无法加价。
- **删除当前标的回未选态**：删除正在使用的标的时 `activeId` 必须回退为 `null`（保持"未选择"），而不是自动选中第一个——避免"标的复活 + 误选中"的诡异体验。

## 为什么值得

这些用例不是 KPI 装饰，而是每次 `npm run build` 与发版前的**安全网**：88 个用例覆盖了报价校验、状态机、成交规则、模板闭环等全部高风险路径。功能可以迭代，规则不能回退——回归测试就是这句话的保证。
