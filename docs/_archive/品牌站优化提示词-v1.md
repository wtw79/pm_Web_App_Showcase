### 1.3 功能模块清单（按真实代码能力，共 7 大模块）

1. **控制台报价**（src/modules/Console.jsx + src/logic/auction.ts）
   - 应价 + 号牌双输入、触屏软键盘（布局可配置）
   - 报价规则自动校验：增价不低于起拍价、减价不高于起拍价（移植 WPF `ValidatePriceRules`）
   - 撤回上一手、删除任意行 + 精确撤销（`_deletedRows` 撤销栈）、重新开始（快照可恢复）
   - 暂停 / 恢复；成交前二次校验；成交锁定（成交价/号牌/时间落库）；流拍标记
   - 领先 / 出局 / 成交三态状态机（最新在前，报表渲染时重算不信任持久化）
   - 下一手建议价自动计算（基准 + 幅度 × 方向）

2. **副屏投屏**（electron/window-manager.cjs + src/components/bigscreen/*）
   - 欢迎页（PDF 播放 / 图片轮播）与竞价页（4 大字卡 + 报价表）独立投屏
   - 多显示器可分别指定目标屏幕；无边框、置顶、全屏、DPI 自适应
   - 大字卡 FitText 等比缩放防溢出；领先号牌自动高亮
   - 投屏实时预览（帧流推送，主路径 `webContents.capturePage`，降级 desktopCapturer）
   - 投屏窗崩溃自动重启（最多 3 次，控制台实时感知）
   - PDF 用 pdf.js canvas 纯净渲染（不用 Chromium 内置查看器）

3. **标的管理**（src/modules/Lots.jsx + src/models/target.ts）
   - 增删改查、设为当前；Excel 13 列模板批量导入/导出（支持回导）
   - 搜索 + 分页；批量操作（删除 / 流拍 / 暂停 / 恢复 / 清空）
   - 标的详情四页签（资料 / 媒体 / 键盘 / 历史）；独立路由浏览详情
   - 标的级媒体：欢迎页 PDF、欢迎页图片、竞价页图片

4. **成交归档与报表**（electron/ipc-hub.cjs `save-deal-artifact` + src/utils/excel.js）
   - 成交瞬间自动生成《拍卖记录表》Excel（对齐 pm 模板：45 轮/页、买受人签名区）+ 现场截图 jpg
   - 自动落 `数据/{标的}/` 目录（报表 + 截图 + template/ 模板副本 + config 快照 + logs 审计）
   - 全部成交 / 流拍汇总报表导出
   - 截图可靠性：轮询「已成交」弹窗渲染完成后 capturePage，空帧重试，前端 canvas 快照兜底
   - `deal_artifacts` 台账（SQL 落库，可追溯）

5. **文件管理**（V2.3.00 新增，electron/files-ipc.cjs + src/modules/Files.jsx）
   - 逻辑视图（按标的聚合：欢迎页 PDF / 欢迎页图片 / 竞价页图片 / 报表 / 截图）+ 类型视图下拉筛选（全部媒体含 PDF / 全部图片 / 全部 PDF / 报表 / 截图）
   - 分组导入可设为标的字段（欢迎页 PDF → welcomePdf、欢迎页图片 → welcomeImages、竞价页图片 → media）
   - 图片 / PDF 内嵌预览（官方 pdf.js viewer）、下载导出、多选 zip 打包
   - 删除进系统回收站（可恢复，媒体列表引用同步移除）；重命名 / 移动 / 复制 / 新建文件夹
   - 归档目录外部变更自动同步（fs.watch 防抖 500ms）
   - 安全：路径白名单防穿越（越权返回 `B-02-001`）、显示归档相对路径不暴露本机绝对路径

6. **公式引擎与配置**（src/logic/formula.ts + src/models/target.ts）
   - G4 公式引擎：Cn4-Cn7 参数列实时计算（默认 `DD/C1`、`DD/C2`、`DD/(C1*C2)`，可配置）
   - 变量 DD=当前总价，C1-C4=按标的录入的参数值；参数列 / 参数名可配置
   - 除零 / 语法错 / 空公式一律返回 0（对齐 WPF `catch→0`）

7. **桌面端工程化与系统设置**
   - 三主题换肤（控制台 + 投屏全套统一）；系统级单一背景、主副标题两页共用
   - 系统初始化模板导入 / 导出（设置 + 键盘布局），配置一次多机复用
   - 数据目录可配置（默认安装目录/AuctionData，可迁任意目录，重启生效），便于备份迁移
   - 统一错误码体系（A-BB-CCC 分层 + traceId 全链路审计，失败可回溯）
   - 持久化防抖（主进程 500ms 防抖落盘 + 退出强制 flush）、报价关键操作 <100ms 即时上屏
   - 自动更新（静默升级）+ 系统托盘；NSIS 安装包；`contextIsolation` + 受控 preload 安全模型

## 第二篇 · 品牌站优化提示词（审查通过后全文交给 AI 执行）

### 0. 角色与任务

你是一位资深产品站设计师 + 前端工程师。请基于「拍卖竞价显示系统」（V2.3.00）的真实能力，重构现有品牌展示站，让产品被目标用户（拍卖行/拍卖师/现场操作员/主办方管理层）快速看懂、信任、愿意试用。**全程必须符合"事实准确、不夸大"的红线**。

5. **P1 · "6 大功能"文案过时**：现为 7 大模块（新增文件管理），所有"6 大/六大"表述更新为 7。

### 2. 项目背景（必须使用的事实，禁止编造）

- 产品：拍卖竞价显示系统（Auction Bid Console），拍卖会现场一体化工具，个人独立开发维护
- 版本 V2.3.00 · 自 2021 年桌面版持续迭代至今 · React 18 + Vite 5 + Electron 33 + sql.js
- 7 大功能模块：控制台报价 / 副屏投屏 / 标的管理 / 成交归档与报表 / 文件管理 / 公式引擎与配置 / 桌面端工程化
- 88 个自动化测试用例（L1 接口 / L2 逻辑 / L3 数据库 / L4 结构校验，实测 84 运行 + 4 性能）
- 3 套主题（现代青绿 / 深空科技 / 玻璃渐变）· 45 轮/页规范报表 · 2 屏独立投屏 · 0 网络依赖离线可用

### 3. 设计原则

#### 3.1 内容真实性铁律（最高优先级）

1. **所有数字必须来自事实表**（88 测试 / 45 轮 / 3 主题 / V2.3.00 / 2021 起 / 7 模块），不得自行推导或美化。
2. **"个人维护项目"定位必须诚实呈现**，不伪装成团队/公司产品；不写"领先/唯一/第一"等绝对化表述。
3. **能力边界要讲清**：演示版 ≠ 桌面版（副屏物理投屏 / SQLite / 文件系统仅桌面版）；展示站不含源代码与 exe。
4. 功能描述沿用 FAB 叙述法（特性 → 作用 → 利益）并配痛点对照，像"给懂行的人看"而不是"给投资人看"。

#### 3.2 差异化卖点（必须重点呈现，这是现有站最缺的）

现有品牌站把这些藏在细节里，重构时要把它们提到显眼位置：

1. **断网也能跑**：桌面端零网络依赖，弱网现场照常开拍 —— 对手（在线 SaaS）做不到
2. **一个人能操作**：触屏软键盘 + 规则自动校验 + 一键撤回，不需要专人盯守
3. **落槌即归档**：成交瞬间自动出《拍卖记录表》+ 现场截图 + 按标的归档，散场零加班
4. **可追溯可审计**：成交锁定不可篡改、统一错误码 + traceId 全链路、配置变更审计日志 —— 司法/典当场景刚需
5. **工程可信度**：88 个自动化测试分层护航、5 年迭代（2021→2026）、WPF 行业桌面版规则对齐
6. **文件管理内置**：归档整理收进系统内，不用开文件管理器（V2.3.00 新能力）

#### 3.3 视觉与体验

- 品牌色：现有 `brand`（青绿 #0E7C86 系）延续即可，与系统默认主题「现代青绿」一致，强化"拍卖现场的沉稳专业感"
- 中文排版优先，字体层级清晰；避免模板感（现站 Sidefolio 模板痕迹较重，重点是去模板化、去装饰性残留）
- 首页 Hero 建议直接用**真实系统截图/大屏投屏效果图**（替换现 CSS 手绘示意），配 5 秒内的产品价值定位
- 每个功能模块配真实截图 + FAB 三行说明；场景页配"改造前 vs 改造后"对照
- 动效克制：仅 hover 反馈与入场动画，不影响阅读与加载
- 移动端必须可用（现站已做抽屉导航 + 演示门控，保留）
