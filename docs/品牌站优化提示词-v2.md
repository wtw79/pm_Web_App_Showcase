## 第零篇 · 定位宣言（v2 核心，先读这段）

系统本身是不可见的：它是代码、规则、数据流、一次次的成交记录。它没有形态，无法被相遇。

**品牌站 = 这个系统的身体。** 它把不可见的系统呈现为可感知的存在：

1. **看见系统（而不是被推销）**：访问者走进来，看到的是一个"活着的、在场的东西"——它有形态（三主题界面、大屏、控制台）、有动作（报价、落槌、归档的节奏）、有性格（严谨、克制、一个人维护的诚实）、有历史（2021 年至今的成长）。
2. **无需得到系统**：这里没有"购买 / 授权 / 下载试用"的转化目标。演示版不是"试用装"，而是"你可以隔着窗户看它工作"。
3. **无需成为系统**：访问者不需要学会操作、不需要理解内部机理、不需要成为用户。站在外面看，就能看见它是什么、它怎么活。

**一句话基调**：像策展人为一件作品做展览，而不是销售员向客户做路演。

3. **标的管理**（src/modules/Lots.jsx + src/models/target.ts）
   增删改查、设为当前；Excel 13 列模板批量导入 / 导出（支持回导）；搜索 + 分页；批量操作（删除 / 流拍 / 暂停 / 恢复 / 清空）；标的详情四页签（资料 / 媒体 / 键盘 / 历史）+ 独立路由；标的级媒体（欢迎页 PDF、欢迎页图片、竞价页图片）。

4. **成交归档与报表**（electron/ipc-hub.cjs `save-deal-artifact` + src/utils/excel.js）

6. **公式引擎与配置**（src/logic/formula.ts）

## 第二篇 · 品牌站优化提示词（v2 重写 · 审查通过后全文执行）

### 0. 角色与任务

你是一位数字策展人 + 前端工程师。你的任务不是推销一个软件，而是**为「拍卖竞价显示系统」制造一具身体**：让这个不可见的系统（代码、规则、数据流、五年的维护历史）以可感知的形态存在，让走进这个站点的人**看见它**——看见它的形态、动作、性格与历史。访问者无需购买它，也无需学会使用它；他们只需要能与它相遇。

### 3. 设计原则

#### 3.1 真实性铁律（最高优先级）

1. 所有数字来自第一篇事实表，不得推导或美化。
2. **"个人维护项目"必须诚实呈现**——这不羞耻，这是这个系统的性格之一。
3. 能力边界讲清：演示版 ≠ 桌面版；展示站不含源代码与 exe。
4. 不写"领先 / 唯一 / 第一"等绝对化表述；不编造用户案例与好评。
5. 功能描述沿用 FAB（特性 → 作用 → 利益）+ 痛点对照，但语气是"呈现"而非"说服"。

#### 3.2 可见性哲学（v2 新增，替代原"差异化卖点"）

让访问者**看见**系统，从五个感官通道入手：

1. **形态（看见它长什么样）**：真实界面截图、三主题换装、大屏投屏效果、控制台 / 报表 / 文件管理的真实样子。首屏 Hero 用真实系统截图或投屏效果，替换 CSS 手绘示意。
2. **动作（看见它怎么工作）**：在线演示是"隔窗看它工作"——完整走一遍起拍 → 应价 → 落槌 → 归档的节奏；用 GIF/视频展示投屏实时刷新、成交瞬间截图落盘。
3. **性格（看见它是什么性格）**：严谨（规则自动校验、成交锁定）、可逆（每一步都能撤回）、克制（只做现场该做的事）、诚实（一个人维护、断网能跑）。让性格从文案、细节、交互中透出来。
4. **历史（看见它怎么活到今天）**：版本时间线不是"更新日志"，是成长史——V2.1.55 的奠基、投屏架构重构、88 个测试的守护、文件管理的出生。每一条都是这个系统活过的痕迹。
5. **内部（看见它的构造）**：文档中心是"解剖图"——架构、状态机、数据模型、公式引擎、测试体系。这满足"想深入看的人"，但入口保持轻盈。

#### 3.3 关系与 CTA（v2 重写）

- **访问者与系统的关系 = 观众与作品**，不是客户与产品。
- 在线演示：文案从"试用"改为"看见它工作"（如：**看一场拍卖如何被数字化**）。
- 联系页：不是"商务合作 / 源码授权"为首，而是**"与它的作者聊聊"**——提 issue、交流、合作仍可存在，但姿态是对话不是销售。
- 页脚 / 首页 CTA：指向"去看它工作"（演示）与"看它的构造"（文档），而非"获取它"。
- GitHub：作为"它的出生地 / 病历本 / 开放交流处"呈现。

#### 3.4 视觉与体验

- 延续品牌青绿（#0E7C86 系），与系统默认主题「现代青绿」一致，沉稳专业。

- 移动端可用（保留抽屉导航 + 演示门控）。
